## چرا DNS؟

کامپیوتر ها فقط با  IP address کار می‌کنند (مثل 216.239.38.120) که کار با آن برای انسان بسیار دشوار است پس  DNS یا  Domain Name System این مشکل را حل می‌کند. یعنی اسم های قابل فهم (مثل google.com) را به IP address تبدیل می‌کند.

## فرایند DNS Resolution

این اتفاق چگونه می‌افتد؟

1. اول بررسی cache محلی: سیستم عامل و مرورگر بررسی می‌کند آیا قبلا این IP را یاد گرفته است یا نه(برای سرعت بیشتر).
2. سپس DNS Resolver: اگر در کش نبود درخواست را برای  DNS Resolver که معمولا همان  ISP هست می‌فرستد.
3. و Root DNS Server: اگر جوابی نبود از یک سرور ریشه سوال می‌کند که مسئول پسوند .com کدام سرور است.
4. سپس TLD (Top Level Domain): سرور مسئول .com می‌گوید که مسئول دقیق google.com کدام سرور است.
5. سپس Authoritative DNS Server: این سرور IP دقیق google.com را می‌دهد. 
6. و در نهایت جواب به مرورگر باز می‌گردد و مرورگر می‌تواند با آن وصل شود.

**این ساختار نشان می‌دهد که هیچ سرور واحدی نداریم که همه ی دنیا را بشناسد، بلکه هر کدام در یک سطح عمل می‌کنند و باقی مسیر به عهده بقیه است**.

---
## ساختار دامنه

یک دامنه مانند  www.google.com  راست به چپ خوانده می‌شود.

.com ---> TLD/Top Level Domain
google ---> second-level Domain
www ---> subdomain

---
## انواع رکورد DNS

**هر دامنه در  DNS چند رکورد دارد که اطلاعات مختلفی را نگه داری می‌کند.

- رکورد A: دامنه را به یک آدرس  IPv4 وصل می‌کند.
- رکورد AAAA: دامنه را به یک آدرس IPv6 وصل می‌کند.
- رکورد CNAME: یک دامنه را دامنه دیگری اشاره (alias) می‌دهد.
- رکورد MX: مشخص می‌کند ایمیل های دامنه باید به کدام سرور بروند.
-------
چون درخواست‌های DNS معمولاً کوچک و سریع هستند و نیازی به تضمین ۱۰۰٪ تحویل ندارند (اگر جواب نرسید، دوباره درخواست میدهد)، از **UDP** استفاده می‌کند که سریع‌تر از TCP‌ است ولی تضمین تحویل ندارد.

---
## نگاه عملی

با استفاده از nslookup در می‌توان این مراحل را دید(مثلا با زدن "nslookup google.com" در command prompt).

---
## نگاه امنیتی 

- مثل DNS Spoofing / Cache Poisoning: مهاجم جواب جعلی به DNS resolver میدهد، طوری که کاربر به‌جای سایت واقعی، به یک سایت جعلی (مثلاً صفحه‌ی فیشینگ بانک) هدایت شود.
- مورد بعدی DNS Tunneling: بعضی مهاجمان از پروتکل DNS به‌عنوان یه کانال مخفی برای رد و بدل کردن داده (حتی سرقت اطلاعات) استفاده می‌کنند، چون خیلی از فایروال‌ها ترافیک DNS را کمتر بررسی می‌کنند.
-همچنین  DDoS روی DNS سرورها: اگر یک سرور DNS اصلی از کار بیفتد، همه‌ی سایت‌هایی که به آن وابسته‌ هستند، غیرقابل‌دسترس می‌شوند (همین اتفاق در حمله‌ی معروف Dyn در ۲۰۱۶ افتاد که خیلی از سایت‌های بزرگ دنیا را از کار انداخت).
